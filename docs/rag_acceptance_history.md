# RAG 验收评测历史

本文把已经跑过的评测收在一处。各轮的原始数字仍在各自的报告和 JSON 里，这里只记录口径、结果和前后能对上的变化。

检索指标都按文档名对齐 `relevant_sources`，`top_k=5`：

- **Hit@5**：可答题的 top-5 是否命中至少一篇 gold
- **Recall@5 / MRR@10 / nDCG@10**：可答题的召回和排序
- **Reject@5**：拒答题的 `bait_sources` 没有进入 top-5
- **切片综合成功**：可答命中，或拒答时诱饵未进 top-5，分母含拒答题。2026-11-12 报告里的切片命中率用的是这个口径

延迟都是逐条清缓存后的端到端时间。三轮的设备和精排开关不一样，延迟不能横比。

## 2026-11-13 16:58（Asia/Shanghai）：保位、按文档去重、索引常驻

同一套 1041 题、同一份已入库语料（51 份、7921 个 child chunk）、同一台 release 二进制的后续版本。模型仍是 Xenova `bge-base-zh-v1.5` fp32 ONNX，CPU，1 个会话，Cross-Encoder 关闭。每题先清结果缓存再检索，稀疏索引在入库后保持，不再每题重建。基线是上一节的 `full_1041.json`。

改动：

- 原始查询的 dense、sparse 各自前 2 份文档直接占进最终结果，避免融合和关键词门控把两路都已命中的文档丢掉。
- 返回名额按请求的 top_k 给出（评测请求 10，上限 10），不再卡在 3 条引文。同一文档的切块排在不同文档之后。
- 问句在问现行、现在、今天、目前、最新或仍生效时，文件名带 `_2024` 或「已废止」的卷降权。问已废止时刻表本身时不降权。
- 切块写明「不记载 / 没有记载 / 未记载」时，结果 metadata 带 `abstain`。评测另记 Abstain@5，不从结果里删诱饵，Reject@5 的定义不变。
- `POST /retrieval/cache-clear` 只清结果缓存。删文档和重新入库仍会拆掉稀疏索引。

hybrid 的可答 Hit@5 从 933/964 升到 963/964。唯一没进 top-5 的可答题是 `struct_02`。企业 4 道旧失败 `procurement_01`、`faq_04`、`expense_01`、`expense_02` 都已命中。`hp_07`、`tm_04` 也回到 top-5。standard 时效性从 64/77 升到 77/77，单跳事实从 68/77 升到 77/77。15 道三文档多跳（`ex_hp_055`–`ex_hp_069`）Hit@5 已中，但 top-5 里还没有凑齐三份卷宗，所以 Recall@5 不是 100%。

Reject@5 降到 0/77，是因为诱饵文档仍被召回，而且现在 top-5 能放下更多文档。这不是把诱饵藏起来。Abstain@5 是 74/77：返回切块写明该字段未记载。没标上的 3 题是原 standard 的 `reject_01`、`reject_02`、`reject_03`，它们的诱饵正文没有「不记载 / 没有记载 / 未记载」。

延迟是结果缓存清空、稀疏索引保持的数字。上一节 sparse 122 ms、hybrid 184 ms，主要花在每题重建 7921 行 BM25。进程刚启动时的第一条 hybrid 大约 93 ms（含建索引），之后同一条查询在清掉结果缓存后是 77 ms。本表 hybrid p50 60 ms、p95 75 ms，sparse p50 4 ms。dense 的命中数没有变。
